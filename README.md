# Page Observer

Сервис на Go. Периодически загружает HTML-страницы, удаляет указанные пользователем элементы DOM, сравнивает нормализованный текст, сохраняет версии и историю проверок в SQLite. Конкретные изменения доступны в unified diff.

## Запуск

Нужен Go 1.24 или новее. Для обычной сборки C-компилятор не нужен: используется SQLite-драйвер `modernc.org/sqlite`.

```sh
go mod download
go run ./cmd/pageobserver
```

API: http://127.0.0.1:8080. Swagger UI: http://127.0.0.1:8080/docs. Спецификация: http://127.0.0.1:8080/openapi.json. Swagger UI встроен в бинарник и работает без внешнего CDN.

В текущей рабочей папке также собраны готовые Windows-бинарники:

```powershell
.\bin\pageobserver.exe
# В отдельном терминале, для демонстрационных страниц:
.\bin\demo.exe
```

Повторная сборка из исходников:

```sh
go build -trimpath -o bin/pageobserver.exe ./cmd/pageobserver
go build -trimpath -o bin/demo.exe ./cmd/demo
```

Бинарники, тестовые данные `.cache` и переносимый компилятор `.tools` исключены из репозитория.


Параметры:

| Флаг | По умолчанию | Назначение |
|---|---|---|
| `-addr` | `127.0.0.1:8080` | Адрес HTTP API |
| `-db` | `data/observer.db` | Файл SQLite |
| `-workers` | `20` | Максимум одновременно выполняемых проверок |
| `-queue-size` | `100` | Максимум ожидающих заданий |
| `-timeout` | `5s` | Timeout HTTP-запроса, включая redirects и чтение тела |
| `-max-html` | `2097152` | Лимит HTML в байтах, после HTTP-декомпрессии |
| `-versions` | `20` | Число сохранённых версий каждой страницы |
| `-tick` | `100ms` | Период работы scheduler |

```sh
go run ./cmd/pageobserver -workers 5 -queue-size 10 -timeout 3s
```

## API

| Метод | Путь | Результат |
|---|---|---|
| POST | `/pages` | Добавить страницу; `201` |
| GET | `/pages` | Активные страницы; `?includeDeleted=true` включает удалённые |
| GET | `/pages/{id}` | Настройки, состояние и результат последней проверки |
| PATCH | `/pages/{id}` | Изменить URL, interval и/или ignore |
| DELETE | `/pages/{id}` | Прекратить наблюдение; `204` |
| POST | `/pages/{id}/check` | Поставить ручную проверку в общую очередь; `202` |
| GET | `/pages/{id}/history` | Все результаты проверок |
| GET | `/pages/{id}/versions` | Сохранённые версии нормализованного текста |
| GET | `/pages/{id}/changes` | Проверки `changed`, включая diff |
| GET | `/stats` | Счётчики проверок и состояния workers/очереди |
| GET | `/health` | Проверка работоспособности HTTP-сервера |

История, изменения и версии отсортированы от новых к старым. Параметры `limit` (1–500, по умолчанию 100) и `offset` (от 0) задают пагинацию. Ошибки API имеют вид `{"error":"..."}`.

Добавление страницы:

```json
{
  "url": "http://127.0.0.1:8090/page",
  "interval": "2s",
  "ignore": [".clock"]
}
```

`interval` — положительная Go duration, например `500ms`, `30s`, `2m`, максимум `8760h`. URL должен содержать схему HTTP/HTTPS и hostname, без встроенных логина и пароля. `ignore` необязателен, по умолчанию пуст; допускается до 100 корректных CSS-селекторов. Некорректные значения и неизвестные поля JSON возвращают `400`.

Редактирование:

```json
{
  "interval": "5s",
  "ignore": [".clock", "#view-counter"]
}
```

## Планирование и конкурентность

```text
scheduler → bounded channel → fixed worker pool
                                  ↓
                         HTTP GET с context timeout
                                  ↓
                   DOM → ignore → normalize → diff
                                  ↓
                          транзакция SQLite
```

* Новая страница проверяется при ближайшем срабатывании scheduler.
* Состояния страницы: `idle → queued → running → idle`. Проверка может быть только одна: состояние и постановка в очередь изменяются под общим mutex.
* Scheduler выполняет только планирование. Сетевые запросы, HTML-обработка, сравнение и хеширование работают вне общего mutex. Страница остаётся `running` до сохранения результата; перед записью под mutex повторно проверяется удаление страницы.
* Если страница уже `queued` или `running`, очередной временной слот пропускается. Пропущенные проверки не накапливаются. После завершения используется следующий слот расписания.
* При полной очереди страница остаётся `idle` и просроченной: scheduler повторит попытку на следующем tick. Приоритет получают страницы с самым ранним сроком проверки, что предотвращает голодание при перегрузке.
* Ручная проверка использует тот же механизм: `409` для занятой страницы, `503` при полной очереди или завершении сервиса. Она не сбрасывает периодическое расписание.
* PATCH занятой страницы возвращает `409`: изменения можно повторить, когда страница станет `idle`. Это исключает сохранение результата по устаревшим правилам.

История, версии и статистика читаются вне общего mutex движка; контекст HTTP-запроса передаётся в SQL, поэтому отключение клиента отменяет чтение. Для файловой SQLite используется одно соединение записи и отдельный пул до четырёх соединений только для чтения. WAL позволяет сохранять проверки во время чтения истории. `foreign_keys` и `busy_timeout` устанавливаются для каждого нового соединения. Для тестовой БД `:memory:` используется одно общее соединение, поскольку отдельный WAL-пул для неё недоступен.

## Сравнение и хранение

HTML разбирается через `golang.org/x/net/html`, CSS-селекторы — через Cascadia. Все ignore-селекторы сопоставляются с исходным DOM, затем исключаются целые выбранные поддеревья: порядок правил не влияет на результат. Служебные `head`, `script`, `style`, `template` не входят в текст; объявления, часы и другие содержательные элементы исключаются только по правилам пользователя.

Пробельные символы нормализуются внутри текстовых блоков. Границы блоков сохраняются как строки для читаемого diff. HTML entities декодируются; текст inline-элементов не получает искусственных пробелов. Изменения атрибутов, CSS и изображений не отслеживаются. JavaScript не выполняется. Кодировки HTML преобразуются в UTF-8; расширение при декодировании также ограничено.

Первая успешная проверка — `initial`. Следующие — `unchanged` или `changed`. При `unchanged` новая полная версия не создаётся, но запись истории сохраняется и ссылается на существующую версию.

Изменение ignore list или URL устанавливает постоянный флаг `baselinePending`. **Следующая успешная загрузка** обрабатывается по новым правилам и создаёт `baseline` без diff. Ошибка загрузки не сбрасывает этот флаг; он сохраняется и после restart. Изменение одного interval не сбрасывает baseline.

Сохраняются последние `-versions` полных версий каждой страницы: время, HTTP status, нормализованный текст, SHA-256 и размер исходного HTML. Сохранение версии, результата проверки, baseline и удаление старых версий выполняются одной транзакцией. История хранится целиком, включая самостоятельный diff: удаление старой версии не удаляет историю изменения, а `versionId` такой записи становится отсутствующим. Исходный HTML не сохраняется.

DELETE выполняет soft delete. История и версии остаются доступны, страница исключается из планирования. Ожидающая проверка пропускается, выполняющаяся отменяется; её результат не сохраняется после удаления. Восстановление удалённой страницы не предусмотрено: можно добавить URL заново.

После restart активные страницы восстанавливаются с состоянием `idle` и проверяются при ближайшем tick; старые задания не воспроизводятся. Настройки, история, версии и счётчики остаются в SQLite. Используется один процесс сервиса на один файл БД: распределённый scheduler не реализован.

Счётчики `/stats` и сумма длительностей обновляются в той же транзакции, что и история проверки. Запрос статистики читает одну строку, не пересчитывая всю историю. При первом запуске новой версии на существующей БД счётчики автоматически восстанавливаются из истории один раз. Текущие `pages`, `queued` и `running` снимаются отдельно от постоянных счётчиков и могут отражать немного другой момент времени.

## Ошибки и завершение

Каждый завершённый запрос получает отдельную запись истории: `timeout`, `http_error`, `dns_error`, `connection_error`, `tls_error`, `network_error`, `non_html`, `html_too_large`, `parse_error` или `cancelled`. HTTP status сохраняется при наличии. После ошибки периодическое наблюдение продолжается; предыдущая успешная версия остаётся основанием сравнения.

Принимаются успешные HTTP `2xx` с `Content-Type: text/html` или `application/xhtml+xml`. Неверный/отсутствующий тип — `non_html`. Тело читается не более чем до лимита плюс один байт; превышение — `html_too_large`, даже если HTTP status равен 200. `4xx/5xx` — `http_error`. Поддерживаются redirects 301/302/307/308, максимум 10 переходов; сохраняются original URL, final URL и цепочка целевых URL. Переход HTTP → HTTPS не меняет ID наблюдаемой страницы.

`/stats` содержит постоянные счётчики всех проверок (включая удалённые страницы), changed, ошибок, timeouts, HTTP 4xx/5xx и среднюю длительность, а также текущее количество активных страниц, queued/running и настройки workers/очереди. В `errors` входят non-HTML и превышения лимита; cancelled не считается ошибкой.

SIGINT (`Ctrl+C`) и SIGTERM останавливают приём jobs и HTTP-запросов, отменяют текущие запросы и завершают workers. После завершения транзакций закрывается SQLite. Задания, которые не начали выполняться, не получают записи истории и будут запланированы снова после restart.

API по умолчанию слушает localhost. Он рассчитан на локальную демонстрацию/доверенную сеть и разрешает проверку локальных URL, чтобы использовать демонстрационный сервер. Авторизация пользователей и ограничения доступа к внешним/внутренним сетям не входят в реализацию.

Защита от SSRF не реализована: пользователь с доступом к API может инициировать HTTP/HTTPS-запросы к внутренним ресурсам, доступным из среды приложения, в том числе через redirects, и читать сохранённый нормализованный HTML-контент. Не публикуйте API для недоверенных пользователей. Для публичного размещения нужны авторизация и ограничения исходящих соединений с проверкой DNS и каждого redirect.

## Демонстрация

Запустите в двух терминалах:

```sh
go run ./cmd/demo
go run ./cmd/pageobserver -workers 2 -queue-size 3 -timeout 5s
```

Демонстрационные URL:

| URL на `http://127.0.0.1:8090` | Поведение |
|---|---|
| `/page` | HTML с меняющимися часами `.clock` |
| `/static` | Стабильный HTML, изменяемый через `/change` |
| `/slow?delay=3s` | Медленная страница для проверки отсутствия дублей |
| `/slow?delay=10s` | Timeout при стандартном лимите 5s |
| `/error` | HTTP 500 |
| `/pdf` | Не-HTML |
| `/large` | HTML размером 3 MiB |
| `/redirect` | Redirect 302 на `/page` |
| `POST /change` | Увеличить номер версии полезного содержимого |

Пример для PowerShell:

```powershell
$api = 'http://127.0.0.1:8080'
$page = Invoke-RestMethod "$api/pages" -Method Post -ContentType 'application/json' -Body '{"url":"http://127.0.0.1:8090/page","interval":"2s","ignore":[]}'
Start-Sleep -Seconds 5
Invoke-RestMethod "$api/pages/$($page.id)/changes"
Invoke-RestMethod "$api/pages/$($page.id)" -Method Patch -ContentType 'application/json' -Body '{"ignore":[".clock"]}'
Start-Sleep -Seconds 5
Invoke-RestMethod "$api/pages/$($page.id)/history"
Invoke-RestMethod 'http://127.0.0.1:8090/change' -Method Post
Start-Sleep -Seconds 3
Invoke-RestMethod "$api/pages/$($page.id)/changes"
Invoke-RestMethod "$api/stats"
```

Порядок защиты: сначала показать `initial` и `changed` из-за часов, затем добавить `.clock`, увидеть `baseline` и `unchanged`, изменить содержимое через `POST /change` и показать diff. Добавить `/static` для первого `initial → unchanged`, несколько `/slow?delay=3s` с interval `1s` для очереди/workers и отсутствие дублей. Добавить `/error`, `/slow?delay=10s`, `/pdf`, `/large`; показать результаты истории. Завершить сервис через Ctrl+C, запустить снова с тем же `-db` и показать сохранённые данные и возобновлённые проверки. HTTP → HTTPS проверяется автоматическим тестом с локальным TLS-сервером.

## Проверки

```sh
go test ./...
go test -race ./...
go vet ./...
```

Race detector требует CGO и C-компилятор: на Linux обычно достаточно GCC; на Windows — совместимого MinGW-w64/LLVM-MinGW. В этой рабочей папке переносимый LLVM-MinGW размещён в `.tools` (не входит в репозиторий). Для Windows предусмотрен скрипт:

```powershell
./scripts/test.ps1
./scripts/test.ps1 -Race
```

Тесты используют временные SQLite-файлы и `httptest` HTTP/HTTPS-серверы; доступ к реальным сайтам не нужен. Покрываются сценарии раздела 27 ТЗ, а также atomic enqueue, переполнение очереди, конкурентные API-запросы, baseline, сохранность diff при очистке версий, soft delete и отмена при shutdown. В GitHub Actions запускаются обычные тесты, race detector и vet.

## Docker

```sh
docker build -t pageobserver .
docker run --rm -p 127.0.0.1:8080:8080 -v pageobserver-data:/app/data pageobserver
```

В контейнере приложение слушает `0.0.0.0:8080`; указанная публикация порта ограничивает доступ на хосте адресом `127.0.0.1`. Это снижает риск внешнего доступа к API, но не устраняет SSRF: запросы выполняются из сети контейнера.

Образ запускается от непривилегированного пользователя. Named volume сохраняет SQLite при пересоздании контейнера. Для bind mount каталог должен быть доступен UID 65532 на запись.

## Структура

```text
cmd/pageobserver/       запуск API и graceful shutdown
cmd/demo/               управляемые HTML-страницы для защиты
internal/observer/      scheduler, workers, HTTP, DOM, diff, SQLite, тесты
internal/api/           HTTP handlers, OpenAPI, локальный Swagger UI, тесты
scripts/test.ps1        запуск проверок на Windows
```

Swagger UI 5.17.14 распространяется по Apache-2.0; лицензия находится в `internal/api/swagger/LICENSE`. Библиотеки и их версии зафиксированы в `go.mod`/`go.sum`.
